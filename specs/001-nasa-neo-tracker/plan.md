# Implementation Plan: NASA NEO Tracker

**Branch**: `001-nasa-neo-tracker` | **Date**: 2026-10-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-nasa-neo-tracker/spec.md`

## Summary

NASA NEO Tracker — настольное графическое приложение на Python для загрузки
сведений NASA NeoWs о сближениях с Землёй за одну выбранную дату. План
разделяет GUI, валидацию, HTTP-клиент, разбор ответа и кэш. Сетевой запрос
выполняется в рабочем потоке, а результат передаётся в главный поток Tkinter
через очередь и `after`. Последний успешный непустой набор сохраняется
атомарной заменой JSON-файла в пользовательской папке приложения.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: Только стандартная библиотека: `tkinter`, `tkinter.ttk`,
`urllib.request`, `json`, `datetime`, `threading`, `queue`, `os`, `pathlib`,
`tempfile` и `unittest`/`unittest.mock`.

**Storage**: `%LOCALAPPDATA%\NASA-NEO-Tracker\cache.json` на Windows; каталог
создаётся автоматически, а в тестах путь подменяется временным каталогом.
Исходный код и кэш разделены.

**Testing**: `python -m unittest discover -s tests -v`; сохранённые JSON-фикстуры,
`unittest.mock` для HTTP и `tempfile.TemporaryDirectory` для кэша.

**Target Platform**: Desktop с Python 3.11+ и установленным Tkinter; Windows
является основной средой лабораторной работы, проект не использует
платформенные сторонние зависимости.

**Project Type**: Desktop GUI application.

**Performance Goals**: Главное окно не блокируется во время запроса; конечный
тайм-аут HTTP — ровно 15 секунд; после получения результата состояние GUI
обновляется через главный поток. После ошибки кнопка снова доступна для ручного
повтора.

**Constraints**: Без сторонних зависимостей приложения; ключ API только из
`NASA_API_KEY`, с допустимым fallback `DEMO_KEY`; ключ не хранится в репозитории
и не показывается пользователю; пустые/некорректные данные не заменяют пригодный
кэш.

**Scale/Scope**: Один локальный пользователь, один запрос за одну дату, один
последний кэш, таблица результатов NASA NeoWs; без сервера, аккаунтов, графиков,
экспорта и стороннего API.

**Structure Decision**: Выбран один небольшой пакет исходников без лишних
слоёв. `main.py` является точкой входа, собирает зависимости и управляет
сценарием загрузки и восстановления из кэша. `ui.py` содержит только виджеты
Tkinter, отображение состояния и callbacks действий пользователя; HTTP-запросы
и работа с файлами в `ui.py` не выполняются. `nasa_client.py`, `parser.py` и
`cache.py` не обновляют Tkinter. Сетевой запрос выполняется в рабочем потоке,
результат передаётся через `queue.Queue`, а виджеты обновляются только в
главном потоке через `after`.

## Implementation Sequence

1. Создать модели результатов, статусов и ошибок.
2. Реализовать строгую валидацию даты без сетевого доступа.
3. Реализовать разбор NASA JSON с выбором `close_approach_data` за запрошенный
   день и проверкой числовых значений.
4. Реализовать HTTP-клиент с ключом из окружения, тайм-аутом и нормализацией
   HTTP/сетевых/API-ошибок.
5. Реализовать кэш в пользовательской папке с версией формата, атомарной
   заменой и сохранением старого файла при ошибке записи.
6. На отдельной TEST-ветке создать unit-тесты и фикстуры для этапов 2–5,
   включая повторный запрос после ошибки и подмену пути кэша временным
   каталогом; затем выполнить единую команду тестов.
7. Собрать Tkinter-интерфейс, очередь рабочего потока и обновление через
   `after`; проверить состояния загрузки, успеха, ошибки и кэша.
8. Выполнить сценарии из [quickstart.md](./quickstart.md), проверить отсутствие
   ключей в отслеживаемых файлах и подготовить Pull Request.

## Design Decisions

- Запрос всегда передаёт одинаковую выбранную дату в `start_date` и `end_date`.
- Время получения фиксируется после успешного чтения и разбора ответа, в
  локальной временной зоне, в ISO 8601.
- Свежие данные считаются пригодными только после успешной проверки структуры,
  наличия хотя бы одной строки и всех обязательных значений строки.
- При ошибке свежего запроса сначала сохраняется исходное состояние таблицы,
  затем загружается последний пригодный кэш; ошибка записи кэша не отменяет
  показ свежих данных.
- Ошибка чтения повреждённого кэша отображается отдельно и не удаляет файл
  автоматически, чтобы сохранить материал для диагностики.
- Запись без названия или без сближения за выбранную дату пропускается с
  предупреждением; числовые пропуски отображаются как «Нет данных», а пропуск
  признака опасности — как «Неизвестно».
- При использовании `DEMO_KEY` показывается заданное уведомление без значения
  ключа; при HTTP 429 применяется кэш и сохраняется возможность повтора.

## Delivery Gates

- **SPEC**: документы спецификации и планирования подготавливаются, коммитятся
  в отдельной ветке, проходят Pull Request и сливаются в `main`.
- **IMPL**: отдельная ветка создаётся от обновлённой `main`; реализация
  подтверждается ручными smoke-проверками, затем проходит Pull Request и
  слияние.
- **TEST**: отдельная ветка создаётся от обновлённой `main`; в ней создаются
  unit-тесты и фикстуры, выполняется полная проверка, вносятся необходимые
  исправления, после чего оформляется Pull Request и выполняется слияние.

Полная приёмка проекта возможна только после успешного завершения TEST-этапа и
прохождения единой команды unit-тестов без реального NASA API.
